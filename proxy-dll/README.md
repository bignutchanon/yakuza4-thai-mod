# dinput8.dll — source

`dinput8.dll` in the release zip is a small proxy DLL that makes Thai tone and vowel marks stack on their consonant in Yakuza 4 Remastered (Steam). This folder holds its full source so anyone can read it and build it.

Antivirus engines flag the DLL heuristically (for example `Trojan:Win32/Wacatac.B!ml` / `Program:Win32/Wacapew.C!ml`, the `!ml` suffix meaning a machine-learning guess). It patches the game's code in memory and waits in a loop for the game's DRM to unpack, which is the pattern those models score as suspicious.

## What it does

1. **Proxy.** The game imports `DirectInput8Create` from `dinput8.dll`. This DLL exports that one function and forwards the call to the real `dinput8.dll` in the Windows system folder (`GetSystemDirectoryA` + `LoadLibraryA`).
2. **Worker thread.** `DllMain` starts one thread. The thread:
   - waits until the SteamStub DRM has decrypted the game's code (it compares 10 known bytes at the patch site), then waits another 12 seconds so the unpacker finishes;
   - writes three patches into `Yakuza4.exe` memory, in its own process only:
     - **mark stacking:** a 5-byte `jmp` at image base + `0x6750f3` to a small code cave at + `0x120425b` (unused padding inside the exe image). The cave decides from a 256-byte table whether the current text byte is a Thai combining mark and adjusts the pen advance so the mark draws over the previous consonant;
     - **kerning:** zeroes the rows for bytes `0xA1–0xFB` in the game's two static kerning tables (+ `0x12903d4`, + `0x128ebd4`), so Latin-1 kerning stops squeezing Thai letters. It first checks a known value in the table and skips the patch if the exe is a different build;
     - **centering:** a `jmp` at + `0x66ff33` to a 33-byte cave that skips the width count for Thai combining marks, so centred Thai text is not shifted left;
   - then loops every 200 ms and re-applies a patch if the unpacker overwrote it.
3. **Log.** It appends status lines to `y4thai_proxy.log` next to the DLL.

It does not use the network, the registry or any other process, and it writes no files except that log. Delete `dinput8.dll` to turn it off; the game files on disk are never modified.

The only machine code it writes into the game is the two byte arrays `CAVE` and `MEAS_CODE` in `dinput8.cpp`. Their disassembly is in [`patch_disasm.asm`](patch_disasm.asm).

## Build

Needs Visual Studio Build Tools with the C++ x64 toolset. Edit the `vcvars64.bat` path in `build.bat` if your Visual Studio version or folder differs, then run:

```
build.bat
```

Output: `dinput8.dll`. A rebuild will not match the shipped file byte-for-byte, because MSVC stamps the build time into the PE header. The code is the same.
